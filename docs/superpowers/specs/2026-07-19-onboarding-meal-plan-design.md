# Design Spec: AI Daily Meal Plan Generation & Database Sync

## 1. Goal & Context
During the onboarding funnel, we present the user with "Your custom plan" displaying target calorie/macro intakes, predicted weight trajectory, and a daily 4-meal plan preview. Currently, the meal plan preview relies on pre-seeded mock recipes. We want this daily plan to be dynamically generated by Gemini 3.5 Flash AI based on their biometrics and dietary exclusions, grounded with a search in the database/USDA cache to ensure precise nutrient profiles. Once the user completes sign-up, this customized plan must be saved in Supabase under `meal_plans` so they can access it, view full recipes, and log their planned meals directly to their diary.

---

## 2. Supabase Edge Function: `generate-meal-plan`
A new Edge Function will be created to handle the meal plan calculation and AI generation.

* **Path:** `supabase/functions/generate-meal-plan/index.ts`
* **Access:** Anonymous / Unauthenticated allowed (guest friendly).
* **Request Body Schema:**
  ```json
  {
    "gender": "male" | "female",
    "age": number,
    "weight_kg": number,
    "height_cm": number,
    "activity_level": "sedentary" | "lightly_active" | "moderately_active" | "very_active",
    "health_goal": "lose_weight" | "maintain_weight" | "gain_weight",
    "diet_type": "classic" | "vegetarian" | "vegan" | "keto" | "low_carb",
    "exclusions": string[],
    "country": "EG" | "GB"
  }
  ```

* **Calculation Logic:**
  - Mifflin-St Jeor formula to determine BMR and TDEE:
    - BMR (Male) = `10 * weight_kg + 6.25 * height_cm - 5 * age + 5`
    - BMR (Female) = `10 * weight_kg + 6.25 * height_cm - 5 * age - 161`
    - TDEE Multipliers: Sedentary (1.2), Lightly Active (1.375), Moderately Active (1.55), Very Active (1.725)
    - Deficit/Surplus: Lose Weight (-500 kcal, clamp at min 1200 kcal), Gain Weight (+300 kcal), Maintain (0)
  - Macronutrient calculations:
    - Protein: `weight_kg * 2.0` (in grams)
    - Fat: 25% of target calories (1g fat = 9 kcal)
    - Carbs: remaining calories (1g carb = 4 kcal, clamp at min 50g)
    - Water: `weight_kg * 35` (ml, rounded to nearest 250ml)

* **AI Generation Prompt (Gemini 3.5 Flash):**
  - Prompt instructions to build exactly 4 meals: `breakfast`, `lunch`, `dinner`, and `snack`.
  - The sum of calorie/macro counts across all 4 meals must be close to the computed daily targets.
  - Adhere to the user's `diet_type` and `exclusions`.
  - Prioritize `country` culinary styles (Egyptian cuisine for `EG`, British for `GB`).
  - Output JSON conforming to:
    ```json
    {
      "meals": {
        "breakfast": {
          "title_en": "String", "title_ar": "String",
          "description_en": "String", "description_ar": "String",
          "ingredients": [ { "name_en": "String", "name_ar": "String", "weight_g": number, "est_calories_per_100g": number, "est_protein_per_100g": number, "est_carbs_per_100g": number, "est_fat_per_100g": number } ],
          "steps_en": ["String"], "steps_ar": ["String"],
          "tags": ["String"]
        },
        "lunch": { ... },
        "dinner": { ... },
        "snack": { ... }
      }
    }
    ```

* **Grounded Nutrient Verification:**
  - For each generated ingredient:
    1. Query the `foods_cache` database table using `.ilike('name_en', normalized)`.
    2. If a match is found in the cache, overwrite the ingredient's macros per 100g with the database-cached USDA/OFF certified values.
    3. If not found in the local cache, perform a fetch call to the USDA FoodData Central API using the `USDA_API_KEY` (configured on Supabase). Extract certified energy, protein, carbohydrate, and fat values. If the API fails or is not matched, fall back to the AI-estimated nutrient parameters.
    4. Upsert any new dynamically fetched/estimated food details to the `foods_cache` table (setting source to `usda` or `gemini` accordingly).
    5. Re-run macro math using the portion weight (`weight_g`) to compute the final, precise total calories/macros for each meal, ensuring mathematical consistency.
  - Consolidate all verified ingredients to build a unified `grocery_list`.

## 3. Zustand Store (`store/useDiaryStore.ts`)
* Add `activeMealPlan` state to the `DiaryState` store:
  ```typescript
  export interface MealPlanMeal {
    title_en: string;
    title_ar: string;
    description_en: string;
    description_ar: string;
    ingredients: {
      name_en: string;
      name_ar: string;
      weight_g: number;
      calories_per_100g?: number;
      protein_per_100g?: number;
      carbs_per_100g?: number;
      fat_per_100g?: number;
    }[];
    steps_en: string[];
    steps_ar: string[];
    total_calories: number;
    total_protein_g: number;
    total_carbs_g: number;
    total_fat_g: number;
    tags: string[];
    image_url: string;
  }

  export interface MealPlan {
    id?: string;
    title: string;
    meals: {
      breakfast: MealPlanMeal;
      lunch: MealPlanMeal;
      dinner: MealPlanMeal;
      snack: MealPlanMeal;
    };
    grocery_list: { name_en: string; name_ar: string; weight_g: number }[];
    created_at?: string;
  }
  ```
* Add `activeMealPlan: MealPlan | null` to `DiaryState`.
* Modify `syncToSupabase` to also upsert `activeMealPlan` to the Supabase `meal_plans` table if present.
* Modify `fetchFromSupabase` to select the user's latest meal plan from `meal_plans` and write it to `activeMealPlan`.
* Add action `setActiveMealPlan(plan: MealPlan | null)`.

## 4. UI Screen Integrations

### Onboarding Calculations (`app/onboarding.tsx`)
- In Step 3, instead of simulating progress via a timeout, execute a `fetch` request calling `/functions/generate-meal-plan`.
- Increment the loading progress indicator smoothly while waiting.
- Save the returned profile biometrics, computed targets, and the generated `activeMealPlan` into the Zustand store.
- Navigate to `/onboarding_results`.
- Add a try/catch block: if the API call fails or times out, fall back to matching local recipes from `localRecipes` so the flow never halts.

### Onboarding Results (`app/onboarding_results.tsx`)
- Display the computed daily targets, weight trajectory, and daily meal plan preview from Zustand's `activeMealPlan`.
- Fall back to the legacy `localRecipes` filter-matching behavior if `activeMealPlan` is not found.
- The instructions and ingredients of the generated plan remain locked under the blur overlay, prompting users to claim it by signing up.

### Dashboard Quick Logging (`app/(tabs)/index.tsx`)
- Inside the "Meal Logs Bento Grid":
  - Check if `activeMealPlan` exists.
  - For each category (`breakfast`, `lunch`, `dinner`, `snacks` mapped to `snack` in meal plan):
    - If today's logs for that slot are empty:
      - Display a custom card showing the planned meal details: *"Recommended: [Meal Title] ([Calories] kcal)"*.
      - Add a `[Log to Diary]` CTA button. When tapped, it parses the planned meal ingredients and logs it as a food entry for today, automatically updating the daily macro wheels.

### Recipes Screen "Daily Plan" Tab (`app/(tabs)/recipes.tsx`)
- Add a new tab segment: **"Your Daily Plan"** alongside "My Recipes" and "Pantry Search".
- Show the 4 generated meals with complete details fully unlocked (since the user is logged in).
- Provide ingredients lists, directions, and a `[Log to Diary]` button for each meal.

## 5. Verification Plan
* **Automated & Manual Tests:**
  1. Complete the onboarding quiz under a simulated "sedentary / lose weight" goal.
  2. Verify that the calculations loading screen successfully invokes the Edge Function and fetches the personalized plan.
  3. Verify that signing up and verifying OTP syncs the new meal plan to Supabase under the `meal_plans` table.
  4. Verify that logging in on a fresh state pulls the plan from Supabase.
  5. Check Dashboard quick log: tap a meal log slot recommendation and confirm it logs macros correctly.
  6. Verify the "Your Daily Plan" tab displays correctly in `recipes.tsx`.
